# 0006 – Release 0.0.2

- **Status:** in progress
- **Date:** 2026-10-16
- **PR:** release 0.0.2
- **Related plans:** [0005 First release 0.0.1](0005-first-release-0-0-1.md)

## Why

The `0.0.1` release run was cancelled after 14m18s while building the arm64 image under QEMU, so neither the image nor the chart was published (`helm show chart oci://ghcr.io/dbslone/charts/hermes-operator --version 0.0.1` returns 403/not found). The gateway chart in `gateway-helm` now depends on this chart and cannot build until it exists. `0.0.1` is not reused; see the risk note in plan 0005.

## What changes

| Change | Detail |
| --- | --- |
| Version **0.0.2** | `Chart.yaml` `version`/`appVersion`, MCP `serverInfo` version, README dependency example. |
| Faster image build | Already on `main` (`4f5e609`): the build stage runs on `$BUILDPLATFORM` and cross-compiles, with Go cache mounts, QEMU removed and the GHA layer cache enabled. Expected to cut the release from 10+ minutes to a few. |
| Image source label | `LABEL org.opencontainers.image.source` in the Dockerfile links the ghcr image package to this public repo, so it inherits public visibility. Closes the first follow-up of plan 0005. |

## Risks, rollout, rollback

- The chart package (`oci://ghcr.io/dbslone/charts/hermes-operator`) is not linked to the repo by a label. If it is created private, set it to public in the package settings (GitHub does not allow this via API).
- Roll back by deleting the `0.0.2` tag and packages; consumers should pin to a version that exists.

## Follow-ups

- Make `release.yaml` require a green `ci` for the tagged commit.
